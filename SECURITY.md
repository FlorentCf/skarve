# Security

Use GitHub private vulnerability reporting under the repository's **Security →
Report a vulnerability** menu. Do not place secrets or exploit details in a
public issue. If that menu is unavailable, withhold sensitive details and ask
the maintainer to enable the private reporting channel.

Include the affected version, input contract, reproduction with synthetic data,
expected boundary and observed behavior. Do not include production data,
credentials or third-party systems without authorization. No response SLA is promised.

Skarve validates its source identities, dimensions, finite values, geometry and
explicit allocation limits. Applications remain responsible for URL allowlists,
authorization, filesystem access and process/container limits. An engine memory
budget does not account for every GDAL/codec allocation or all process RSS.
Only load the native library from a trusted installation; override paths are
expert deployment settings, not untrusted request inputs.

Release CI runs deterministic tests, bulk ABI checks and dependency review.
These checks are scoped evidence, not a proof that arbitrary native input is safe.
Optional benchmark reference engines do not participate in default execution.
