# Execution choices

Native strict fractional coverage remains the ordinary default. Unprepared
source queries are first-class; caches and persistent summaries are optional
accelerations with measurable build, storage, memory and source-update costs.
The original source can remain the boundary-value authority.

The optional pinned exactextract C++ backend delegates fractional coverage and
five common reductions over Skarve-interpreted binary64 source windows. It uses
the same owned session/source/query surface, with an explicit policy and returned
provenance. It does not impersonate native strict, integer counts, spherical
coverage or ordered selected-buffer reductions.

`auto` with no accepted-policy override stays native. A request accepting only
the exactextract policy can select that backend when installed and eligible.
Accepting both policies does not assert a speed advantage or bitwise equivalence.
The [beta.2 benchmark](../benchmarks/beta2/report/REPORT.md) supports explicit
exactextract policy selection with disclosed trade-offs. It does not justify
performance-based switching between accepted policies. Native remains the
automatic default; an EE-only accepted-policy request remains eligible for EE.
Feature-sequential and raster-sequential strategies each have measured losses,
so polygon count alone does not determine a universally faster choice.

The current package passes its independent strict and matching-upstream checks.
The historical isolated adapter fails its multiband identity controls and is
excluded from speed ratios; its original failed measurements remain in the
report. That finding does not change the current runtime or the preserved beta.1.

The embedded bridge avoids a mandatory Python worker and intermediary feature
property tree. Its trade-offs are cooperative cancellation, finite typed result
staging and serialized upstream execution across sessions. It does not inherit
a separate worker's hard kill or process-memory isolation. Requests that need
those properties are ineligible for the embedded runtime.

Performance claims belong to the generated, pinned benchmark report. Compare
its exact native identity, source interpretation, calculation policy, cache
state, complete useful result and lifecycle costs. A different implementation
can remain faster. Historical results from another artifact or dataset are
not measurements of this candidate.

Skarve combines independently authored source/session systems engineering with
established geometric and aggregation methods and attributed upstream libraries.
It makes no claim to have invented zonal statistics. Source license grants and
binary distribution obligations remain distinct; see
[RUNTIME_LICENSES.md](RUNTIME_LICENSES.md) and [third-party notices](../THIRD_PARTY.md).
